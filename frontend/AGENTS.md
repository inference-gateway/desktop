# AGENTS.md - Frontend

State lives in context stores: the main one in `frontend/store.tsx` (`useDesktop`) and one per feature in `frontend/stores/` (`useActivity`, `useAgents`, `useBackend`, `useComputers`, `useGit`, `useNavigation`, `usePromptQueue`, `useRooms`, `useSelection`, `useSidebar`, `useSnippets`, `useStatus`), each with its own context so its readers re-render only when that feature changes. New feature state goes in `frontend/stores/`, not in the main store. The main store holds chat sessions and gives two hooks: `useDesktop` for sessions and actions, and `useChatStream` for what changes on every agent event (transcripts, items, token usage, run labels). A component reads `useChatStream` only if it shows the stream. The typed Tauri client and transcript state machine live in `frontend/lib/`.

## DOM contract (load-bearing)

- Native `<select id="model-select">` named `Model`, in the bar above the composer (not a custom dropdown). The macOS driver finds it by that name.
- The status bar's mode button is named by its mode's description - `Standard mode - protected tool actions ask first`, `Plan mode - the agent plans before it changes anything`, `Auto mode - tool actions run without asking`, `Auto with judge mode - a judge model decides protected tool actions` - and a click moves to the next mode, as Shift+Tab in the composer does.
- A single native, **uncontrolled** `<textarea id="prompt-input">`.
- Exact button names: visible text `Approve`, `Deny`, `Accept`, `Approve each step`, `Reject` (the plan card), `Save agent`, `New agent`, `Take over`, `Hand back`, `New workspace`, `Save workspace`, Enter in the name, context or namespace field moves focus to the next one. **Detect clusters** and **Provision local cluster** live on the Compute tab, and so do the local cluster's folders: per folder `cluster-folder-name-<n>`, `cluster-folder-path-<n>` and `cluster-folder-read-only-<n>`, where Enter in the name moves focus to the path.
- Secret form inputs in Settings > Secrets keep their ids (`secret-label`, `secret-variable`, `secret-value`, `secret-computer`, `secret-workspace-<name>`). Enter in the label or variable field moves focus to the next one.
- MCP server form inputs in Settings > MCPs keep their ids (`mcp-name`, `mcp-url`, `mcp-image`, `mcp-port`, `mcp-computer`, `mcp-workspace-<name>`, and per header `mcp-header-name-<n>`, `mcp-header-prefix-<n>`, `mcp-header-variable-<n>`). - Speech settings live in Settings > Voice samples and keep their ids: `tts-enabled`, `tts-model` (a native `<select>`), `tts-voice`, `tts-auto-download`, `tts-output-dir` and `tts-require-approval`, and `voice-test-text`, the text a voice sample's test reads. - The avatar test in Settings > Avatars keeps its ids: `avatar-test-text`, the line a test speaks, `avatar-test-voice` (a native `<select>`), the voice it speaks in, and `avatar-model` (a native `<select>`), the model that lip-syncs every talking clip. It saves as it changes.
- The Hugging Face search in Settings > Models keeps its id, `hub-search`. Enter in it searches.
- Agent editor inputs keep their ids (`agent-name`, `agent-description`, `agent-model`, `agent-workspace`, `agent-project`, `agent-instructions`, `agent-emoji`, and `agent-mcp-<server>` per MCP server). Enter in the name or description field moves focus to the next one, which is how the e2e `type` step fills the form.
- Drag sources and targets the drag specs use: a sidebar chat row's title, `Select project <name>`, media pool rows named by their `media/<file>` path, lanes labelled `<Video|Audio|Overlay|Captions> lane <id>`, `Toggle todo panel`, and `Todo status: <status>`, with each todo's grip just left of its status button.
- Shallow DOM: `App` renders `<header id="top-bar">` + `<div id="main">` into `#app`, no wrapper.
