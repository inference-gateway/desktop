# One-click export/import of the full desktop config (#166)

State before this feature:

| State | Location | Owner |
|---|---|---|
| Settings-managed fields | `~/.infer/config.yaml` via `DesktopConfig` (config.rs) | desktop |
| Sidebar projects (names/contexts/groups/paths/assignments) | `~/.infer/projects.json` (agent.rs read/write_projects) | desktop |
| A2A agents | `~/.infer/agents.yaml` (CLI-owned; desktop shells out to `infer agents`) | CLI |
| Scheduled jobs | `~/.infer/schedules/*.yaml` (scheduler.rs reads raw yaml files) | CLI daemon |
| Snippets + skills registry URL | browser localStorage only (frontend/lib/snippets.ts, skills.ts) | desktop |

Design (implemented in backend/src/export.rs, new module):

- One internal `DesktopExport` struct (version, config, projects, agents, schedules, snippets, skills_registry_url, skills) serialized as JSON, YAML or TOML (`toml` crate added). Import parses by trying yaml -> toml -> json (JSON is valid YAML so first match wins) and rejects anything without `version == 1`.
- Machine paths (`storage_directory`, `projects_root`, `sqlite_path`, projects.json `paths` overrides) are stored `~/`-relative at export and re-expanded against the importing machine's $HOME before `merge_config` writes config.yaml - so config.yaml keeps the existing absolute-path semantics and `config_from_value`'s tilde expansion is untouched.
- Credentials never leave the machine: `postgres_password`, `redis_password`, `d1_api_token` are blanked in the export; `auth.json` keys are never read for the export. On import, blanked values do not overwrite non-empty local values.
- Export targets: filesystem via native dialog (tauri-plugin-dialog, Rust-side blocking API, no capability changes) or a private GitHub repo - `gh api repos/<repo> --jq .private` must be "true"; a missing repo is created private; public repos are rejected. Contents-API PUT/GET on the repo root (trunk, flattened filename `infer-desktop-export.<ext>`). `GH_TOKEN` env passed to gh only when the user typed a token.
- projects.json: export is the raw value; import merges (names union, assignments/contexts/groups/paths merged per key, existing keys preserved).
- agents.yaml is CLI-owned: export carries the parsed `A2aAgent` list (`infer agents list`), import re-adds missing agents via `infer agents add/update` (never parses the CLI's yaml).
- Installed skills are exported as names and reinstalled via `infer skills install <name> --user` on import; failures are returned as warnings, not fatal.
- Snippets + skills registry URL now persist in `~/.infer/desktop.json` (commands `read_desktop_data`, `save_desktop_snippets`, `save_skills_registry_url`); localStorage stays as the synchronous cache/fallback.
- Schedules round-trip as raw YAML values (filename -> value) so CLI-written fields survive untouched; import refuses filenames with separators (traversal guard).
- Testable core is `build_export(home)` / `apply_export_files(&export, home)` / `parse_export` (all rooted at a passed home, no global env); tauri commands are thin wrappers. Round-trip unit tests live in export.rs: export from a temp home, serialize in all three formats, apply into a fresh home, re-export and require equality; config merge keeps pre-existing unrelated keys; secrets stay out of the serialized file.
